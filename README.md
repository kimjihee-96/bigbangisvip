# 작물 수익 예측 서비스

## 사용자와 목표

- 사용자: 재배할 작물의 예상 수익을 알아보고 싶은 청년 농부
- 목표: 작물 이름과 예측 조건을 설정하고, 입력한 내용을 확인한다.
- 완료 조건: 작물 이름, 예측 기간, 생산비 반영 여부를 검토하고 설정 완료 화면에 도달한다.

## 사용자 흐름

1. 정보 활용에 동의하고 시작 버튼을 누른다. 안내 팝업을 확인한 뒤 설정을 시작한다.
2. 작물 이름을 입력한다. 비어 있으면 같은 단계에서 입력 안내를 받는다.
3. 예측 기간을 3개월, 6개월, 12개월 중 선택한다. 생산비를 반영하려면 체크박스를 선택하고 낮음, 보통, 높음 중 하나를 고른다.
4. 작물 이름과 예측 조건을 확인한다. 수정이 필요하면 이전 단계로 돌아가 고친다.
5. 설정 완료 안내를 확인한다. 필요하면 ‘다시 설정하기’를 눌러 처음부터 설정한다.

## 5주차 이메일 신청 인터랙션 구현

### 사용자 행동
사용자가 이메일 주소를 입력하고 '작물 수익 예측 소식 신청하기' 버튼을 누른다

### 화면 변화
- 이메일을 입력하지 않으면 입력 안내 문구가 나오고, 이메일 입력 칸이 선택되어 바로 입력할 수 있게 된다.
- 이메일을 입력하고 신청하면 해당 주소와 함께 신청 완료 문구가 표시된다.
- 완료 문구는 연한 초록색 배경과 진한 초록색 글씨로 표시된다.
- 버튼 문구가 '신청 완료'로 바뀌고, 회색으로 표시되며 다시 누를 수 없게 된다.

### 연결한 코드
- querySelector로 신청 폼, 이메일 입력 칸, 버튼, 안내 문구 영역을 선택했다.
- addEventListener로 폼의 submit 이벤트를 handleSubscribe 함수와 연결했다.
- preventDefault로 폼 제출 시 새로고침을 막았다.
- value.trim()으로 이메일 앞뒤 공백을 제거하고, 빈 값이면 안내 문구를 표시한 뒤 focus()로 입력 칸에 커서를 이동했다.
- makeSubscribeMessage 함수로 완료 문구를 만들고 textContent로 화면에 표시했다.
- classList.add("is-success")로 완료 스타일을 적용했다.
- 버튼의 textContent를 변경하고 disabled를 true로 설정했다.

### 화면 크기에 따른 스타일 수정
신청 결과와 비활성화 버튼의 스타일을 모바일용 미디어 쿼리 밖으로 옮겨 큰 화면과 작은 화면 모두에 적용하도록 수정했다.

### 구현 범위
실제 이메일 발송이나 서버 저장 없이, 현재 페이지에서 신청 결과를 보여주는 기능이다.

## 6주차 이벤트와 탭 UI 구현

### 사용자 행동과 화면 변화
- 테마 변경 버튼을 누르면 화면 색과 버튼 문구가 바뀐다.
- 작물 이름을 입력하거나 지우면 현재 글자 수가 표시된다.
- 안내 확인 체크박스를 선택하면 안내 문구와 스타일이 바뀌고, 예상 수익 계산하기 버튼이 활성화된다. 해제하면 다시 비활성화된다.
- 수익 예측, 이벤트 활용, 소식 신청 탭을 누르면 선택한 탭의 설명만 표시된다.

### 연결한 코드
- addEventListener로 click, input, change 이벤트를 연결했다.
- textContent, classList, disabled로 문구와 스타일, 버튼 상태를 변경했다.
- querySelectorAll과 forEach로 여러 탭에 클릭 이벤트를 연결했다.
- data-target으로 탭과 설명 영역을 연결하고 hidden으로 표시 여부를 변경했다.

### 테스트 결과
- 1100px, 768px, 390px에서 화면이 잘리거나 가로 스크롤이 생기지 않는 것을 확인했다.
- 테마 변경 시 화면 색과 버튼 문구가 함께 바뀌었다.
- 작물 이름을 입력하거나 지우면 글자 수가 바로 반영되었다.
- 체크박스 선택과 해제에 따라 안내 문구, 스타일, 버튼 활성화 상태가 정상적으로 바뀌었다.
- 탭을 누르면 선택된 탭과 연결된 설명 하나만 표시되었다.
- Console에 오류가 없는 것을 확인했다.

### 이전 과제 피드백 반영
이메일 신청 완료 문구에 ‘작물별 가격 동향과 수익 예측 소식’을 명시했다.
사용자가 신청한 이메일 주소와 받을 소식의 종류를 함께 확인할 수 있도록 개선했다.

## 7주차 사용자 흐름과 인터랙션 구현

### 구현 내용

기존 동의 체크박스와 시작 버튼에 안내 팝업을 연결했다.
작물 이름 입력 → 예측 조건 선택 → 내용 확인 → 설정 완료로 이어지는 사용자 흐름을 구현했다.

### 인터랙션 시나리오

- 시작과 안내 팝업 : 동의 체크박스를 선택하고 시작 버튼을 클릭하면 안내 팝업이 열린다. 확인 버튼을 누르면 작물 이름 입력 단계로 이동한다. ‘돌아가기’ 또는 Esc로 닫으면 동의를 해제하고 설정 영역을 숨긴다.

- 작물 이름 입력 : 다음 버튼을 클릭하면 앞뒤 공백을 제거한 입력값이 비어 있는지 검사한다. 비어 있으면 ‘작물 이름을 입력해 주세요.’라는 문구와 오류 테두리를 표시하고 입력칸을 선택한다. 값이 있으면 저장하고 조건 선택 단계로 이동한다.

- 예측 기간 선택 : 슬라이더에서 input 이벤트가 발생하면 선택한 기간을 개월 단위로 표시한다.

- 생산비 선택 : 체크박스에서 change 이벤트가 발생하면 생산비 수준 선택 영역을 표시하거나 숨긴다. 확인 화면에는 선택한 수준 또는 ‘미반영’을 표시한다.

- 내용 확인과 수정 : 작물 이름, 예측 기간, 생산비 반영 여부를 확인한다. ‘수정하기’를 누르면 값을 유지한 채 조건 선택 단계로 돌아간다. 작물 이름도 이전 버튼으로 돌아가 수정할 수 있다.

- 설정 완료 : ‘설정 완료하기’를 클릭하면 완료 안내를 표시한다.

- 다시 설정 : ‘다시 설정하기’를 클릭하면 작물 이름, 오류 문구, 확인 내용을 비운다. 예측 기간은 6개월, 생산비는 미반영, 생산비 수준은 보통으로 초기화하고 첫 입력 단계로 돌아간다. 기존 동의 상태는 유지한다.

### 테스트 결과

- 정상 진행 : 동의와 안내 확인 후 작물 이름과 예측 조건을 입력하니, 내용 확인과 설정 완료까지 정상적으로 진행되었다.

- 빈 입력 : 작물 이름을 비우거나 공백만 입력하면 오류 문구와 빨간 테두리가 표시되고, 다음 단계로 넘어가지 않았다. 이름을 입력한 뒤에는 정상적으로 진행되었다.

- 조건 반영 : 선택한 예측 기간이 개월 단위로 표시되었다. 확인 화면에도 작물 이름, 예측 기간, 생산비 수준이 반영되었으며, 생산비를 선택하지 않으면 ‘미반영’으로 표시되었다.

- 이전과 수정 : 이전 단계로 돌아가도 입력값이 유지되었고, 값을 수정하면 확인 화면에도 수정한 내용이 반영되었다.

- 팝업 취소 : ‘돌아가기’와 Esc로 팝업을 닫으면 동의가 해제되고 시작 버튼이 비활성화되었다.

- 다시 설정: 작물 이름과 오류·확인 문구가 지워지고, 예측 기간은 6개월, 생산비는 미반영으로 초기화되었다. 첫 입력 단계로 돌아왔으며 동의 상태는 유지되었다.

- 반응형 화면 : 1100px, 768px, 390px에서 입력창과 버튼이 겹치거나 잘리지 않았고, 각 단계의 기능을 조작할 수 있었다.

### 구현 범위

현재는 작물 수익 예측에 필요한 조건을 설정하고 확인하는 프로토타입이다.
실제 수익 계산이나 서버 저장은 아직 구현하지 않았다.

## 중간고사: 재배 계획 저장 기능

### 새로 추가한 기능

7주차의 예측 조건 설정 완료 화면에 재배 계획 저장 기능을 추가했다.
완료한 조건을 목록에 저장하고, 저장한 내용을 다시 열거나 삭제할 수 있다.

### 사용자와 목적

- 사용자: 여러 재배 조건을 정리하고 확인하려는 청년 농부
- 목적: 설정한 작물 이름, 예측 기간, 생산비 조건을 계획별로 보관하고 다시 확인한다.
- 주요 행동: 조건 설정 완료 → 계획 저장 → 목록에서 내용 보기 또는 삭제

### 사용자 행동과 화면 반응

1. 계획 저장
- 행동: 설정 완료 후 ‘재배 계획 저장하기’를 누른다.
- 조건: 설정이 완료되었으며 같은 조건의 계획이 목록에 없는지 확인한다.
- 성공 반응: 목록에 작물 이름이 추가되고 저장 완료 문구가 표시된다.
- 다음 행동: ‘내용 보기’로 저장한 조건을 확인하거나 다른 계획을 설정한다.

2. 중복 저장
- 행동: 같은 작물 이름과 예측 조건을 다시 저장한다.
- 조건: 동일한 계획이 이미 저장되어 있는지 확인한다.
- 다른 분기의 반응: 중복 안내를 표시하고 목록에는 추가하지 않는다.
- 다음 행동: 기존 계획을 확인하거나 조건을 바꿔 저장한다.

3. 저장한 내용 보기
- 행동: 목록에서 ‘내용 보기’를 누른다.
- 화면 반응: 저장 당시의 작물 이름, 예측 기간, 생산비 조건이 표시된다.
- 다음 행동: 내용을 닫고 다른 계획을 확인할 수 있다.

4. 계획 삭제와 빈 목록
- 행동: 목록에서 ‘삭제’를 누른다.
- 화면 반응: 선택한 계획을 삭제하고 삭제 안내를 표시한다.
- 다른 분기의 반응: 마지막 계획까지 삭제하면 빈 목록 안내가 표시된다.
- 다음 행동: 예측 조건을 설정한 뒤 새로운 계획을 저장할 수 있다.

### 연결한 코드

- click 이벤트로 저장, 내용 보기, 닫기, 삭제 동작을 연결했다.
- 배열에 저장 당시의 조건을 별도 객체로 보관했다.
- some()으로 같은 조건의 계획이 있는지 확인했다.
- createElement()와 textContent로 목록과 상세 내용을 표시했다.
- 삭제 후 목록을 갱신하고, 남은 계획이 없으면 빈 목록 안내를 표시했다.

### 테스트 결과

- 정상 저장: 설정을 완료하고 저장하니 목록에 작물 이름과 저장 안내가 표시되었다.
- 중복 저장: 같은 조건을 다시 저장하면 중복 안내가 표시되고 목록 개수는 늘어나지 않았다.
- 내용 확인: ‘내용 보기’를 누르니 저장 당시의 작물 이름, 개월 수, 생산비 조건이 표시되었다.
- 다른 계획 설정: 다시 설정하여 새 계획을 저장해도 이전 계획이 유지되었다.
- 삭제와 빈 목록: 선택한 계획만 삭제되었고, 모두 삭제하면 빈 목록 안내가 표시되었다.
- 반응형 화면: 1100px, 768px, 390px에서 목록과 버튼이 잘리거나 겹치지 않고 조작되었다.

### 구현 범위

계획 목록은 현재 페이지를 열어둔 동안 유지되며 새로고침하면 초기화된다.
실제 수익 계산이나 서버 저장은 구현하지 않았다.
