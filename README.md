# 작물 수익 예측 서비스

## 사용자와 목표

- 사용자: 재배할 작물의 예상 수익을 알아보고 싶은 청년 농부
- 목표: 작물 이름과 예측 조건을 설정하고, 입력한 내용을 확인한다.
- 완료 조건: 작물 이름, 예측 기간, 생산비 반영 여부를 검토하고 설정 완료 화면에 도달한다.

## 사용자 흐름

1. 정보 활용에 동의하고 시작 버튼을 누른다. 안내 팝업을 확인한 뒤 설정을 시작한다.
2. 작물 이름을 입력한다. 비어 있으면 같은 단계에서 입력 안내를 받는다.
3. 예측 기간을 3개월, 6개월, 12개월 중 선택한다. 생산비를 반영하려면 체크박스를 선택하고 낮음, 보통, 높음 중 하나를 고른다.
4. 작물 이름과 예측 조건을 확인한다. 수정이 필요하면 이전 단계로 돌아가 고친다.
5. 설정 완료 안내를 확인한다. 필요하면 ‘다시 설정하기’를 눌러 처음부터 설정한다.

## 5주차 이메일 신청 인터랙션 구현

### 사용자 행동
사용자가 이메일 주소를 입력하고 '작물 수익 예측 소식 신청하기' 버튼을 누른다

### 화면 변화
- 이메일을 입력하지 않으면 입력 안내 문구가 나오고, 이메일 입력 칸이 선택되어 바로 입력할 수 있게 된다.
- 이메일을 입력하고 신청하면 해당 주소와 함께 신청 완료 문구가 표시된다.
- 완료 문구는 연한 초록색 배경과 진한 초록색 글씨로 표시된다.
- 버튼 문구가 '신청 완료'로 바뀌고, 회색으로 표시되며 다시 누를 수 없게 된다.

### 연결한 코드
- querySelector로 신청 폼, 이메일 입력 칸, 버튼, 안내 문구 영역을 선택했다.
- addEventListener로 폼의 submit 이벤트를 handleSubscribe 함수와 연결했다.
- preventDefault로 폼 제출 시 새로고침을 막았다.
- value.trim()으로 이메일 앞뒤 공백을 제거하고, 빈 값이면 안내 문구를 표시한 뒤 focus()로 입력 칸에 커서를 이동했다.
- makeSubscribeMessage 함수로 완료 문구를 만들고 textContent로 화면에 표시했다.
- classList.add("is-success")로 완료 스타일을 적용했다.
- 버튼의 textContent를 변경하고 disabled를 true로 설정했다.

### 화면 크기에 따른 스타일 수정
신청 결과와 비활성화 버튼의 스타일을 모바일용 미디어 쿼리 밖으로 옮겨 큰 화면과 작은 화면 모두에 적용하도록 수정했다.

### 구현 범위
실제 이메일 발송이나 서버 저장 없이, 현재 페이지에서 신청 결과를 보여주는 기능이다.

## 6주차 이벤트와 탭 UI 구현

### 사용자 행동과 화면 변화
- 테마 변경 버튼을 누르면 화면 색과 버튼 문구가 바뀐다.
- 작물 이름을 입력하거나 지우면 현재 글자 수가 표시된다.
- 안내 확인 체크박스를 선택하면 안내 문구와 스타일이 바뀌고, 예상 수익 계산하기 버튼이 활성화된다. 해제하면 다시 비활성화된다.
- 수익 예측, 이벤트 활용, 소식 신청 탭을 누르면 선택한 탭의 설명만 표시된다.

### 연결한 코드
- addEventListener로 click, input, change 이벤트를 연결했다.
- textContent, classList, disabled로 문구와 스타일, 버튼 상태를 변경했다.
- querySelectorAll과 forEach로 여러 탭에 클릭 이벤트를 연결했다.
- data-target으로 탭과 설명 영역을 연결하고 hidden으로 표시 여부를 변경했다.

### 테스트 결과
- 1100px, 768px, 390px에서 화면이 잘리거나 가로 스크롤이 생기지 않는 것을 확인했다.
- 테마 변경 시 화면 색과 버튼 문구가 함께 바뀌었다.
- 작물 이름을 입력하거나 지우면 글자 수가 바로 반영되었다.
- 체크박스 선택과 해제에 따라 안내 문구, 스타일, 버튼 활성화 상태가 정상적으로 바뀌었다.
- 탭을 누르면 선택된 탭과 연결된 설명 하나만 표시되었다.
- Console에 오류가 없는 것을 확인했다.

### 이전 과제 피드백 반영
이메일 신청 완료 문구에 ‘작물별 가격 동향과 수익 예측 소식’을 명시했다.
사용자가 신청한 이메일 주소와 받을 소식의 종류를 함께 확인할 수 있도록 개선했다.

## 7주차 사용자 흐름과 인터랙션 구현

### 구현 내용

기존 동의 체크박스와 시작 버튼에 안내 팝업을 연결했다.
작물 이름 입력 → 예측 조건 선택 → 내용 확인 → 설정 완료로 이어지는 사용자 흐름을 구현했다.

### 인터랙션 시나리오

- 시작과 안내 팝업 : 동의 체크박스를 선택하고 시작 버튼을 클릭하면 안내 팝업이 열린다. 확인 버튼을 누르면 작물 이름 입력 단계로 이동한다. ‘돌아가기’ 또는 Esc로 닫으면 동의를 해제하고 설정 영역을 숨긴다.

- 작물 이름 입력 : 다음 버튼을 클릭하면 앞뒤 공백을 제거한 입력값이 비어 있는지 검사한다. 비어 있으면 ‘작물 이름을 입력해 주세요.’라는 문구와 오류 테두리를 표시하고 입력칸을 선택한다. 값이 있으면 저장하고 조건 선택 단계로 이동한다.

- 예측 기간 선택 : 슬라이더에서 input 이벤트가 발생하면 선택한 기간을 개월 단위로 표시한다.

- 생산비 선택 : 체크박스에서 change 이벤트가 발생하면 생산비 수준 선택 영역을 표시하거나 숨긴다. 확인 화면에는 선택한 수준 또는 ‘미반영’을 표시한다.

- 내용 확인과 수정 : 작물 이름, 예측 기간, 생산비 반영 여부를 확인한다. ‘수정하기’를 누르면 값을 유지한 채 조건 선택 단계로 돌아간다. 작물 이름도 이전 버튼으로 돌아가 수정할 수 있다.

- 설정 완료 : ‘설정 완료하기’를 클릭하면 완료 안내를 표시한다.

- 다시 설정 : ‘다시 설정하기’를 클릭하면 작물 이름, 오류 문구, 확인 내용을 비운다. 예측 기간은 6개월, 생산비는 미반영, 생산비 수준은 보통으로 초기화하고 첫 입력 단계로 돌아간다. 기존 동의 상태는 유지한다.

### 테스트 결과

- 정상 진행 : 동의와 안내 확인 후 작물 이름과 예측 조건을 입력하니, 내용 확인과 설정 완료까지 정상적으로 진행되었다.

- 빈 입력 : 작물 이름을 비우거나 공백만 입력하면 오류 문구와 빨간 테두리가 표시되고, 다음 단계로 넘어가지 않았다. 이름을 입력한 뒤에는 정상적으로 진행되었다.

- 조건 반영 : 선택한 예측 기간이 개월 단위로 표시되었다. 확인 화면에도 작물 이름, 예측 기간, 생산비 수준이 반영되었으며, 생산비를 선택하지 않으면 ‘미반영’으로 표시되었다.

- 이전과 수정 : 이전 단계로 돌아가도 입력값이 유지되었고, 값을 수정하면 확인 화면에도 수정한 내용이 반영되었다.

- 팝업 취소 : ‘돌아가기’와 Esc로 팝업을 닫으면 동의가 해제되고 시작 버튼이 비활성화되었다.

- 다시 설정: 작물 이름과 오류·확인 문구가 지워지고, 예측 기간은 6개월, 생산비는 미반영으로 초기화되었다. 첫 입력 단계로 돌아왔으며 동의 상태는 유지되었다.

- 반응형 화면 : 1100px, 768px, 390px에서 입력창과 버튼이 겹치거나 잘리지 않았고, 각 단계의 기능을 조작할 수 있었다.

### 구현 범위

현재는 작물 수익 예측에 필요한 조건을 설정하고 확인하는 프로토타입이다.
실제 수익 계산이나 서버 저장은 아직 구현하지 않았다.

## 중간고사: 재배 계획 저장 기능

### 새로 추가한 기능

7주차의 예측 조건 설정 완료 화면에 재배 계획 저장 기능을 추가했다.
완료한 조건을 목록에 저장하고, 저장한 내용을 다시 열거나 삭제할 수 있다.

### 사용자와 목적

- 사용자: 여러 재배 조건을 정리하고 확인하려는 청년 농부
- 목적: 설정한 작물 이름, 예측 기간, 생산비 조건을 계획별로 보관하고 다시 확인한다.
- 주요 행동: 조건 설정 완료 → 계획 저장 → 목록에서 내용 보기 또는 삭제

### 사용자 행동과 화면 반응

1. 계획 저장
- 행동: 설정 완료 후 ‘재배 계획 저장하기’를 누른다.
- 조건: 설정이 완료되었으며 같은 조건의 계획이 목록에 없는지 확인한다.
- 성공 반응: 목록에 작물 이름이 추가되고 저장 완료 문구가 표시된다.
- 다음 행동: ‘내용 보기’로 저장한 조건을 확인하거나 다른 계획을 설정한다.

2. 중복 저장
- 행동: 같은 작물 이름과 예측 조건을 다시 저장한다.
- 조건: 동일한 계획이 이미 저장되어 있는지 확인한다.
- 다른 분기의 반응: 중복 안내를 표시하고 목록에는 추가하지 않는다.
- 다음 행동: 기존 계획을 확인하거나 조건을 바꿔 저장한다.

3. 저장한 내용 보기
- 행동: 목록에서 ‘내용 보기’를 누른다.
- 화면 반응: 저장 당시의 작물 이름, 예측 기간, 생산비 조건이 표시된다.
- 다음 행동: 내용을 닫고 다른 계획을 확인할 수 있다.

4. 계획 삭제와 빈 목록
- 행동: 목록에서 ‘삭제’를 누른다.
- 화면 반응: 선택한 계획을 삭제하고 삭제 안내를 표시한다.
- 다른 분기의 반응: 마지막 계획까지 삭제하면 빈 목록 안내가 표시된다.
- 다음 행동: 예측 조건을 설정한 뒤 새로운 계획을 저장할 수 있다.

### 연결한 코드

- click 이벤트로 저장, 내용 보기, 닫기, 삭제 동작을 연결했다.
- 배열에 저장 당시의 조건을 별도 객체로 보관했다.
- some()으로 같은 조건의 계획이 있는지 확인했다.
- createElement()와 textContent로 목록과 상세 내용을 표시했다.
- 삭제 후 목록을 갱신하고, 남은 계획이 없으면 빈 목록 안내를 표시했다.

### 테스트 결과

- 정상 저장: 설정을 완료하고 저장하니 목록에 작물 이름과 저장 안내가 표시되었다.
- 중복 저장: 같은 조건을 다시 저장하면 중복 안내가 표시되고 목록 개수는 늘어나지 않았다.
- 내용 확인: ‘내용 보기’를 누르니 저장 당시의 작물 이름, 개월 수, 생산비 조건이 표시되었다.
- 다른 계획 설정: 다시 설정하여 새 계획을 저장해도 이전 계획이 유지되었다.
- 삭제와 빈 목록: 선택한 계획만 삭제되었고, 모두 삭제하면 빈 목록 안내가 표시되었다.
- 반응형 화면: 1100px, 768px, 390px에서 목록과 버튼이 잘리거나 겹치지 않고 조작되었다.

### 구현 범위

계획 목록은 현재 페이지를 열어둔 동안 유지되며 새로고침하면 초기화된다.
실제 수익 계산이나 서버 저장은 구현하지 않았다.

## 9주차 폼 UI와 입력 경험 설계

### 사용자 행동

사용자가 재배할 작물 이름과 재배 지역을 입력하고, 재배 기간과 생산비 반영 여부를 선택한다. 입력한 내용을 확인한 뒤 재배 계획을 저장하고, 저장한 계획을 다시 열어보거나 취소한다.

### 입력 폼 구성과 조건

- 발표 훈련 예제를 작물 수익 예측 서비스의 재배 계획 작성 폼으로 변경했다.
- 입력 과정을 ‘작물 정보 → 재배 조건 → 내용 확인’의 세 단계로 구성했다.
- 작물 이름은 필수 입력으로 설정하고, 공백만 입력한 값은 허용하지 않도록 했다.
- ‘무’, ‘벼’처럼 한 글자인 작물 이름도 입력할 수 있도록 최소 1자, 최대 60자로 설정했다.
- 재배 지역은 선택 항목으로 설정하고 최대 10자까지 입력하도록 했다.
- 재배 기간은 라디오 버튼으로 3개월, 6개월, 12개월 중 하나를 선택하도록 했다.
- 생산비 반영 여부는 체크박스로 선택하도록 했다.
- 텍스트 입력에는 label의 for와 input의 id를 연결하고, 선택 요소는 label로 감싸 각 항목의 의미를 알 수 있도록 했다.
- 입력 조건과 글자 수를 도움말로 안내하고 aria-describedby로 입력 요소와 연결했다.

### 선택에 따른 조건부 입력

- ‘생산비를 포함할게요’를 선택하면 예상 생산비 수준을 고르는 영역이 나타나도록 했다.
- 생산비 수준은 ‘낮음’, ‘보통’, ‘높음’ 중 하나를 선택하도록 했다.
- 체크를 해제하면 추가 영역을 숨기고 fieldset의 disabled를 true로 설정해 내부 입력 요소를 사용할 수 없게 했다.
- 다시 체크하면 영역을 표시하고 disabled를 false로 변경해 선택할 수 있도록 했다.
- 체크박스의 aria-expanded도 추가 영역의 표시 상태에 맞춰 변경했다.

### 입력 상태와 피드백

- 작물 이름과 재배 지역을 입력하는 동안 현재 글자 수를 표시했다.
- 작물 이름이 입력 조건을 충족하면 ‘입력 조건을 충족했습니다.’라는 문구와 정상 상태 스타일을 표시했다.
- 작물 이름을 비우거나 공백만 입력한 상태에서 다음 단계로 이동하려고 하면 오류 문구를 표시하고 입력 칸으로 포커스를 이동했다.
- 오류가 있는 입력 칸에는 aria-invalid를 적용했다.
- 올바르게 수정하면 오류 문구와 aria-invalid를 제거하고 정상 상태로 변경했다.
- 정상 상태와 오류 상태를 색상뿐 아니라 안내 문구로도 구분했다.
- 이전 단계나 수정 화면으로 돌아가도 입력한 내용이 유지되도록 했다.

### 저장과 결과 처리

- 저장하기 전에 작물 이름을 다시 검사하도록 했다.
- 저장 중에는 ‘저장하는 중...’이라는 버튼 문구와 진행 안내를 표시했다.
- 저장 버튼과 정보·조건 수정 버튼을 비활성화하고, isSubmitting으로 중복 저장 요청을 막았다.
- form의 aria-busy를 변경해 저장 처리 중인 상태를 표시했다.
- 저장에 성공하면 완료 화면을 보여주고 내 계획 목록에서 다시 확인할 수 있도록 했다.
- 저장에 실패하면 입력한 내용을 유지하고 오류 안내를 표시한 뒤 다시 저장할 수 있도록 했다.
- 같은 작물, 지역, 재배 기간, 생산비 조건의 계획이 이미 있으면 중복 안내를 표시했다.
- 실제 서버 요청 대신 브라우저의 localStorage를 사용했다. 저장 중 상태를 보여주기 위해 0.6초 뒤 저장 처리를 실행하도록 했다.

### 다시 작성 기능

- ‘새 계획 만들기’를 누르면 form.reset()으로 입력값과 선택 상태를 초기화했다.
- 작물 이름과 재배 지역의 글자 수를 초기화했다.
- 입력 오류, 정상 상태 표시, 저장 결과 문구, 내용 확인 영역을 초기화했다.
- 생산비 추가 영역을 다시 숨기고 비활성화했다.
- 저장 버튼과 진행 상태를 초기화하고 첫 번째 단계의 작물 이름 입력 칸으로 포커스를 이동했다.

### 연결한 코드

- querySelector로 입력 칸, 도움말, 오류 문구, 버튼, 추가 입력 영역을 선택했다.
- input 이벤트로 글자 수와 입력 상태를 갱신했다.
- validateTitle 함수에서 작물 이름의 필수 입력과 글자 수 조건을 검사했다.
- updateTitleExperience 함수에서 글자 수, 도움말, 정상·오류 스타일을 변경했다.
- change 이벤트와 syncQnaOptions 함수로 생산비 추가 영역의 표시와 비활성화 상태를 변경했다.
- updateSummary 함수로 입력한 내용을 확인 화면에 표시했다.
- setSubmitState 함수로 저장 중·성공·실패 문구와 버튼 상태를 관리했다.
- saveCurrentPlan 함수에서 중복 계획을 검사하고 새 계획의 저장을 처리했다.
- savePlans 함수에서 localStorage에 계획 목록을 저장했다.
- 저장 버튼을 type="submit"으로 설정하고, form의 submit 이벤트에서 입력 검사와 저장을 처리했다.
- preventDefault로 기본 제출에 따른 새로고침을 막았다.

### 실패 처리 조건과 코드 위치

- script.js의 savePlans 함수에서 localStorage 저장 중 오류가 발생하면 catch에서 false를 반환하도록 했다.
- saveCurrentPlan 함수에서 저장 실패를 확인하면 방금 추가한 계획을 목록에서 제거하고 false를 반환하도록 했다.
- 저장 처리 부분에서 실패 결과를 받으면 setSubmitState로 오류 문구를 표시하고 버튼을 다시 사용할 수 있도록 했다. 입력값은 초기화하지 않아 수정하거나 다시 저장할 수 있도록 했다.
- 같은 조건의 계획이 있으면 saveCurrentPlan 함수에서 중복 안내를 표시하고 저장을 중단하도록 했다.

### 기능 확인 순서

1. 작물 이름을 비운 상태에서 다음 버튼을 눌러 오류 안내와 입력 칸 포커스를 확인한다.
2. 공백만 입력했을 때 다음 단계로 넘어가지 않는지 확인한다.
3. 올바른 작물 이름으로 수정해 오류가 해제되고 글자 수와 조건 충족 문구가 표시되는지 확인한다.
4. 생산비 포함을 켜고 끄면서 추가 영역의 표시와 disabled 상태가 함께 바뀌는지 확인한다.
5. 재배 조건을 선택하고 내용 확인 단계에서 입력한 내용이 정확히 표시되는지 확인한다.
6. 정보 수정과 조건 수정을 눌러 이전 입력이 유지되는지 확인한다.
7. 저장 버튼을 눌러 저장 중 문구와 버튼 비활성화, 완료 화면, 저장 목록을 확인한다.
8. 같은 조건의 계획을 다시 저장해 중복 안내와 입력 내용 유지 여부를 확인한다.
9. ‘새 계획 만들기’를 눌러 입력값, 안내 문구, 글자 수, 선택 요소, 버튼 상태가 함께 초기화되는지 확인한다.

### 구현 범위

- 재배 계획을 입력하고 브라우저에 저장하는 수업용 프로토타입으로 구현했다.
- 실제 작물 추천이나 수익 계산, 서버 저장은 구현하지 않았다.

## 10주차 내비게이션과 화면 이동 구현

### 사용자 행동

사용자가 상단 메뉴를 눌러 이용 방법, 계획 만들기, 내 계획 영역으로 이동한다. 작물 정보와 재배 조건을 입력해 계획을 저장하고, 저장된 목록에서 필터를 선택해 원하는 상태의 계획을 확인한다. 모바일에서는 메뉴 버튼을 눌러 메뉴를 펼치고 목적지를 선택한다.

### 메뉴 구성과 목적지

- ‘이용 방법’은 #about에 연결해 서비스 이용 순서를 확인하도록 했다.
- ‘계획 만들기’는 #planner에 연결해 작물 이름, 재배 지역, 재배 기간, 생산비 반영 여부를 입력하도록 했다.
- ‘내 계획’은 #archive에 연결해 저장한 계획을 확인하고 상세 보기, 취소, 취소 되돌리기를 사용할 수 있도록 했다.
- 주요 메뉴는 nav 안에 ul과 li를 넣는 구조로 구성했다.

### 현재 위치 표시

- 주소의 해시 값에 맞는 메뉴에 is-current 클래스를 적용해 글자색, 배경색, 밑줄로 구분했다.
- 현재 메뉴에는 aria-current="page"를 적용하고, 다른 메뉴에서는 제거했다.
- 페이지를 처음 열거나 새로고침할 때 현재 주소에 맞는 메뉴를 표시하도록 했다.
- hashchange 이벤트를 연결해 메뉴 이동과 브라우저 뒤로·앞으로 가기 이후에도 현재 메뉴 표시가 바뀌도록 했다.
- 주소에 해시가 없으면 첫 번째 메뉴인 ‘이용 방법’을 강조하도록 했다.

### 목록 필터와 결과 안내

- 저장된 재배 계획을 ‘전체’, ‘저장됨’, ‘취소됨’으로 나눠 확인하도록 했다.
- ‘전체’에서는 취소 여부와 관계없이 모든 계획을 표시했다.
- ‘저장됨’에서는 cancelled 값이 false인 계획을 표시했다.
- ‘취소됨’에서는 cancelled 값이 true인 계획을 표시했다.
- 필터를 선택하면 해당 버튼에만 is-active 클래스를 적용하고 aria-pressed를 true로 변경했다.
- 나머지 버튼에서는 선택 표시를 제거하고 aria-pressed를 false로 변경했다.
- 선택한 필터에 맞춰 실제 카드 목록과 현재 표시되는 계획 수가 함께 바뀌도록 했다.
- 전체 목록이 비어 있으면 저장한 계획이 없다는 안내와 ‘계획 만들러 가기’ 링크를 표시했다.
- 선택한 필터의 결과만 없으면 조건에 맞는 계획이 없다는 안내를 표시하고, 다른 필터를 선택할 수 있도록 했다.

### 모바일 메뉴 구현

- 화면 너비가 600px 이하일 때 주요 메뉴를 접고 메뉴 열기·닫기 버튼을 표시했다.
- 버튼을 누르면 메뉴의 is-open 클래스를 추가하거나 제거해 메뉴를 펼치고 접도록 했다.
- 메뉴의 실제 표시 상태에 맞춰 버튼 문구와 aria-expanded 값이 함께 바뀌도록 했다.
- 메뉴에서 목적지를 선택하면 해당 영역으로 이동하고 펼쳐진 메뉴가 닫히도록 했다.
- 넓은 화면에서는 메뉴 버튼을 숨기고 주요 메뉴를 가로로 표시했다.
- 모바일 메뉴 링크에 높이와 여백을 적용해 손가락으로 누르기 편하게 했다.
- 다크 모드에서도 선택된 필터의 글씨가 잘 보이도록 색상을 수정했다.

### 연결한 코드

- querySelector와 querySelectorAll로 메뉴, 메뉴 버튼, 필터 버튼, 목록 영역을 선택했다.
- updateCurrentNav 함수에서 현재 주소와 메뉴 링크를 비교해 현재 메뉴를 표시했다.
- addEventListener로 hashchange 이벤트와 메뉴·필터 버튼의 click 이벤트를 연결했다.
- classList.toggle로 현재 메뉴, 선택된 필터, 모바일 메뉴의 펼침 상태를 변경했다.
- setAttribute와 removeAttribute로 aria-current, aria-pressed, aria-expanded를 관리했다.
- getVisiblePlans 함수에서 filter를 사용해 선택한 상태에 맞는 계획을 골랐다.
- renderPlans 함수에서 visiblePlans를 기준으로 카드 목록, 항목 수, 결과 안내를 표시했다.
- 기존 입력 검증, 글자 수 표시, 저장, 상세 보기, 취소·되돌리기 기능을 유지했다.

### 기능 확인 순서

1. ‘이용 방법 → 계획 만들기 → 내 계획’을 차례로 눌러 목적지와 현재 메뉴 표시가 함께 바뀌는지 확인한다.
2. 메뉴로 이동한 뒤 새로고침과 브라우저 뒤로 가기를 실행해 현재 위치 표시를 확인한다.
3. 작물 이름과 재배 조건을 입력하고 계획을 저장한 뒤 ‘내용 보기’에서 저장한 내용을 확인한다.
4. 계획 두 개 중 하나를 취소하고 ‘전체’에는 두 개, ‘저장됨’과 ‘취소됨’에는 각각 한 개가 표시되는지 확인한다. 기존 계획이 있다면 그 수를 함께 고려한다.
5. 결과가 없는 필터를 선택해 안내 문구가 표시되는지 확인하고, 다른 필터를 눌러 목록이 다시 나오는지 확인한다.
6. ‘취소 되돌리기’를 누르고 필터 목록이 바뀌는지 확인한다. 새로고침 후에도 계획과 상태가 유지되는지 확인한다.
7. 화면 너비를 약 390px로 줄여 메뉴 열기·닫기를 실행하고, 목적지를 선택하면 메뉴가 닫히는지 확인한다.
8. 모바일에서도 입력, 저장, 상세 보기, 필터, 취소 기능을 사용하고 버튼과 콘텐츠가 겹치거나 잘리지 않는지 확인한다.

### 구현 범위

- 청년 농부를 위한 작물 수익 예측 서비스의 재배 계획 관리 화면에 적용했다.
- 계획은 브라우저의 localStorage에 저장하도록 했으며, 실제 작물 추천이나 수익 계산, 서버 저장 기능은 구현하지 않았다.

## 11주차 웹 접근성 개선

### 사용자 행동

사용자가 청년 농부를 위한 작물 수익 예측 서비스에서 이용 방법을 확인하고, 재배 계획을 만들고, 저장한 계획을 내 계획 목록에서 확인한다. 사용자는 마우스뿐 아니라 키보드로도 메뉴 이동, 입력, 저장, 상세 보기, 필터 선택, 모바일 메뉴 열기와 닫기를 할 수 있다.

### 이번 주 추가·수정한 기능

- 현재 메뉴와 선택한 필터를 색상만으로 구분하지 않고 굵은 글씨와 밑줄로도 구분했다.
- 정보 전달용 이미지에 서비스 장면을 설명하는 대체 텍스트를 작성했다.
- 브라우저 탭 제목이 현재 메뉴에 맞게 바뀌도록 했다.
- 상세 보기 창의 닫기 버튼에 “재배 계획 상세 닫기”라는 이름을 제공했다.
- 본문 바로가기 링크를 추가해 키보드 사용자가 첫 Tab에서 바로 본문으로 이동할 수 있도록 했다.
- 모바일 메뉴가 열린 상태에서 Esc 키를 누르면 메뉴가 닫히고 초점이 메뉴 버튼으로 돌아가도록 했다.
- 필터를 선택했을 때 현재 표시되는 재배 계획 수와 결과 없음 상태를 문구로 안내했다.
- 필터 결과가 없을 때 “전체 재배 계획 보기”를 제공해 사용자가 다시 목록으로 돌아갈 수 있도록 했다.
- 계획을 취소한 뒤 카드가 사라지는 경우에도 초점이 선택된 필터 버튼으로 이동하도록 했다.
- 오류, 완료, 선택 상태를 색상뿐 아니라 문구와 상태 표시로 함께 알 수 있도록 했다.

### 개선 전 → 개선 후

- 개선 전: 현재 메뉴와 선택한 필터가 색상 위주로만 표시되어 색을 구분하기 어려운 사용자는 현재 위치를 파악하기 어려울 수 있었다.  
  개선 후: 현재 메뉴와 선택한 필터에 굵은 글씨와 밑줄을 함께 적용해 색상 외에도 상태를 구분할 수 있도록 했다.

- 개선 전: 서비스 이미지를 볼 수 없는 사용자는 이미지가 전달하는 장면을 알기 어려웠다.  
  개선 후: 작물 수익 예측 서비스 콘셉트 이미지에 의미가 드러나는 대체 텍스트를 작성했다.

- 개선 전: 메뉴를 눌러도 브라우저 탭 제목은 그대로라 현재 어느 화면을 보고 있는지 알기 어려웠다.  
  개선 후: 이용 방법, 계획 만들기, 내 계획 메뉴에 따라 브라우저 탭 제목이 함께 바뀌도록 했다.

- 개선 전: 모바일 메뉴를 키보드로 열었을 때 Esc 키로 닫는 동작이 없었다.  
  개선 후: Esc 키를 누르면 메뉴가 닫히고 메뉴 버튼으로 초점이 돌아가도록 했다.

- 개선 전: 필터 결과가 없을 때 단순히 결과 없음 안내만 보여 다음 행동이 부족했다.  
  개선 후: 선택한 조건에 맞는 결과가 없으면 “전체 재배 계획 보기” 링크를 제공해 사용자가 전체 목록으로 돌아갈 수 있도록 했다.

- 개선 전: 저장됨 필터에서 계획을 취소하면 카드가 사라지면서 초점이 어색하게 남을 수 있었다.  
  개선 후: 카드가 사라지면 현재 선택된 필터 버튼으로 초점이 이동하도록 해 키보드 흐름을 유지했다.

### 확인한 기능

- Tab 키로 본문 바로가기 링크가 나타나는지 확인했다.
- Enter 키로 본문 바로가기 링크를 실행했을 때 본문 영역으로 이동하는지 확인했다.
- 메뉴를 눌렀을 때 주소, 현재 메뉴 표시, 브라우저 탭 제목이 함께 바뀌는지 확인했다.
- 작물 이름을 비우거나 공백만 입력했을 때 오류 문구와 입력창 초점이 표시되는지 확인했다.
- 생산비 포함을 체크하거나 해제했을 때 추가 선택 영역이 나타나고 사라지는지 확인했다.
- 재배 계획 저장 후 상세 보기 창을 열고 닫기 버튼으로 닫히는지 확인했다.
- 저장됨, 취소됨, 전체 필터를 눌렀을 때 목록 수와 안내 문구가 함께 바뀌는지 확인했다.
- 저장됨 필터에서 계획을 취소했을 때 선택된 필터 버튼으로 초점이 이동하는지 확인했다.
- 모바일 화면에서 메뉴 열기와 닫기, 메뉴 선택 후 자동 닫힘, Esc 키 닫기를 확인했다.

### 구현 범위

10주차까지 만든 청년 농부를 위한 작물 수익 예측 서비스의 재배 계획 관리 화면에 웹 접근성 개선을 적용했다. 실제 작물 추천, 수익 계산, 서버 저장 기능은 구현하지 않았고, 재배 계획은 브라우저의 localStorage에 저장했다.
